# 인류 난제 아카이브

리프 메타(leaf meta)가 만들고 계속 관리한다. 무료로 공개한다. MIT 라이선스다. 복사, 재배포, 인쇄, 수업 자료로 쓸 수 있다.

**이것은 한 번 쓰고 덮는 책이 아니다.** 난제가 풀리거나, 주장이 정정되거나, 새 난제가 등록될 때마다 고쳐 쓰는 저장소다. 바뀐 내용은 지우지 않고 [부록 C 변경 이력](appendix/c-changelog.md)에 날짜와 함께 쌓아서, 그 자체로 "누가 언제 무엇을 풀었는지"에 대한 역사 기록이 되게 한다.

> **기준일 2026-10-24.** 이 저장소의 모든 상태 표기는 이 날짜 기준이다. 난제의 상태는 시간이 지나면 바뀐다. 갱신 방법은 [부록 A](appendix/a-registration.md)에, 바뀐 기록은 [부록 C](appendix/c-changelog.md)에 있다.

## 이 저장소를 만드는 이유

AI가 수학 올림피아드 문제를 풀고, 단백질 구조를 예측하고, 오래된 조합론 문제에 새 구성을 제시하는 시대다. 2026년 하반기에는 OpenAI와 앤트로픽이 몇 주 간격으로 리만 가설, 나비어-스토크스 방정식, 아다마르 추측 같은 오래된 난제에 "진전이 있었다"는 발표를 쏟아냈고, 그만큼 수학계의 검증 논쟁도 커졌다. 동시에 암도, 노화도, 의식의 정체도 여전히 풀리지 않았다. 이 둘 사이의 간격을, 시간이 지나도 계속 고쳐 쓸 수 있는 자리에 모아 둘 필요가 있다고 생각했다.

이 저장소는 세 가지를 한다.

1. **분야별로 난제를 모은다.** 수학, 전산학, 물리학, 생로병사(노화, 질병, 암을 포함한 생물학과 의학), 신경과학과 심리학, 철학, 종교까지 일곱 분야다.
2. **누가, 무엇으로, 어떻게 풀었는지를 기록한다.** 풀린 문제는 해결한 사람(또는 AI)과 증명 방법, 검증 상태까지 적는다. 아직 못 푼 문제는 왜 어려운지를 적는다.
3. **AI 시대에 공개해서, 계속 갱신되게 한다.** 전문 연구자가 아니어도 도전할 수 있고, 그 결과가 투명하게 쌓이도록 [부록 A](appendix/a-registration.md)에 등록 절차를 정해 뒀다. 아직 사람의 검증이 끝나지 않은 AI의 주장도 숨기지 않고 싣되, 검증 상태를 분명히 구분한다. 8부가 그 사례들을 모았고, [부록 D](appendix/d-links.md)에 OpenAI, 앤트로픽, 구글 딥마인드와 이들을 검증하고 추적하는 쪽의 사이트와 깃허브 저장소를 모아 뒀다.

| | |
|---|---|
| 구성 | 8부 20절 (수학, 전산학, 물리학, 생로병사, 신경과학과 심리학, 철학, 종교, AI가 최근 들고 온 결과) |
| 실린 난제 | 107건 |
| 상태 집계 | ✅ 해결 16건, 🟡 부분진행 16건, ⏳ 미해결 52건, ⚠️ 논쟁/정정됨 4건, ❓ 검증 기준 없음 19건 |
| 아직 결론 나지 않은 것 (✅ 외 전부) | 91건 |
| 라이선스 | MIT |

상태 기호의 정의는 [부록 B 표기 범례](appendix/b-legend.md)에 있다. **"⏳ 미해결"은 다섯 상태 중 하나일 뿐, "아직 안 풀린 것 전부"가 아니다.** "해결 기준은 분명한데 아무도 못 푼 경우"만 좁게 가리키는 표기라서, 부분적으로만 진전된 것(🟡)과 해결 주장이 논쟁 중인 것(⚠️), 애초에 검증 방법 자체가 없는 철학과 종교 질문(❓)은 여기 안 잡힌다. 진짜로 아직 결론이 나지 않은 것을 세려면 ✅(해결) 16건을 뺀 나머지, 즉 91건을 봐야 한다.

## 어떻게 읽나

과학과 수학 쪽 부(1~4부)는 표가 "해결자/증명자"와 "방법 요약"을 중심으로 구성된다. 증명과 검증이라는 개념이 분명하기 때문이다.

철학과 종교(6부, 7부)는 다르다. 애초에 수학적 증명이나 실험으로 판가름나는 질문이 아닌 경우가 많다. 그래서 "해결자/증명자" 대신 "주요 입장"을 나열한다. 이 저장소는 어느 쪽이 옳다고 판정하지 않는다.

8부는 AI가 최근 내놓은 결과를 모았다. 발표 당시의 주장과 그 이후 학계의 검증을 분리해서 적는다. 둘이 다른 경우가 실제로 있다.

## 인용하려면

이 저장소를 참고해서 실제로 문제를 풀었다면, 증명이나 논문, 블로그 글에 이 저장소를 인용으로 남겨 둔다. 그래야 나중에 검증할 때 "어떤 항목을 보고 도전했는지"가 분명해진다.

**문제별 인용.** 뷰어에서 문제 번호(예: `1.1`) 칸에 있는 **"인용 복사"** 단추를 누르면, 그 문제를 가리키는 마크다운 링크가 클립보드에 복사된다.

```markdown
[1.1 리만 가설 — 인류 난제 아카이브](https://leaf-kit.github.io/book-humanity-challenges/#/part1/01-number-theory.md#1.1)
```

이걸 그대로 증명 문서나 블로그 글, 논문의 참고문헌 자리에 붙여 넣으면 된다. 깃허브에서 원고를 직접 볼 때도 같은 번호로 된 앵커(`#1.1`)가 걸려 있어서, `github.com/.../blob/main/part1/01-number-theory.md#1.1` 형식으로도 같은 자리를 가리킬 수 있다.

**저장소 전체 인용.**

```
리프 메타(leaf meta). 인류 난제 아카이브. https://github.com/leaf-kit/book-humanity-challenges (접속 YYYY-MM-DD 기준)
```

```bibtex
@misc{leafmeta_humanity_challenges,
  author = {leaf meta},
  title  = {인류 난제 아카이브},
  year   = {2026},
  url    = {https://github.com/leaf-kit/book-humanity-challenges}
}
```

**그다음은 이렇게 진행된다.** 인용 링크와 함께 증명을 공개한 뒤, [부록 A](appendix/a-registration.md)의 절차대로 그 증명 링크를 이 저장소에 등록한다. 검증이 끝나면(동료 심사 통과, 독립 재현 등 분야별 기준은 부록 A를 따른다) 상태가 ✅로 바뀌고, 해당 항목의 "해결자/증명자" 칸에 이름이 올라간다. 즉 **인용 → 증명 공개 → 등록 → 검증 → 해결자/증명자로 기록**, 이 순서로 움직인다.

## 고치고 싶다면

새로운 해결이나 증명을 등록하려면 [부록 A](appendix/a-registration.md)를 따른다. 사실 오류나 출처 오류를 발견하면 이슈로 알려 준다. 해당 부와 번호(예: "4.3")를 함께 적어 주면 빠르다.
